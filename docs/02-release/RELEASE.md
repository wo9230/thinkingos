# v0.1.1-rc1 分发与发布说明

本说明用于将现有 Markdown 核心分发给其他使用者。v0.1.1-rc1 是实验性预发布版，首批真实 Case 验证尚未完成；实际上传和公开状态以对应 GitHub 标签与 Release 为准。分发包不包含外部工作台应用与个人实例。

## 分发内容

[PUBLIC-FILES.txt](PUBLIC-FILES.txt) 是逐文件允许清单，一行一个仓库相对路径。它覆盖主 Skill、Claude 入口、框架、模板、当前契约、明确冻结的设计资产与使用说明。新增公开文件应先审查再加入清单，不能用整个目录递归拷贝代替清单。

`templates/instance/` 中的内容是空白模板；[虚构演示](../00-product/FICTIONAL-WALKTHROUGH.md) 不使用真实资料。用户实例、第三方原件与个人配置均不属于这些公开文件。

维护记录 `memory.md` 用于说明阶段和限制，不能视为使用者事实库或安装时创建真实数据的指令。

## 准备候选

1. 核对当前工作区改动，保留并发编辑；选取已审核的工作区文件快照。
2. 逐文件按清单复制到新的隔离目录，保留两个 Claude 相对符号链接；所有链接最终必须位于候选目录内。
3. 候选不携带原仓库的 `.git/`、`_private/`、`cases/`、本机启动器、模型配置、日志、缓存、备份或密钥。个人截图和真实业务示例不得随包发送。
4. 用本机精确隐私词表扫描候选全文，再检查姓名、联系方式、业务与客户材料、本机路径和常见凭据格式。词表只从私有来源读取，不复制进候选。
5. 人工复核新增与修改文件，以及对外使用说明、示例、文件名、许可和 Git 提交元数据。无匹配仅说明扫描规则未命中。
6. 导出源码压缩包和 SHA-256 文件清单；摘要记录普通文件字节，对符号链接记录相对目标。解包后检查内容与清单完全一致。

维护脚本和一次性测试记录可以留在隔离目录；不为本次发布建设产品运行时或评测系统。

## 候选验收

从不含任何个人实例的副本开始，检查完整依赖、相对链接、Claude 符号链接、目录忽略和入口长度。首次初始化应生成空结构，重复执行应保留已有文件；不能依赖维护者的资料或全局启动器。

用虚构材料检查普通分析、Quick、Full、采访、模板适配和追加复盘。分别记录静态核查、实际模型执行、未执行项与发现的问题；虚构测试不增加首批真实验证计数。不以命令返回成功替代产物和写回范围核查。

ZIP / tar 解包、实际 Git 克隆、Codex / Claude Code 和不同平台应按已测情况分别披露，未测试的不宣称支持已验证。

## Git 历史与公开步骤

- `master` 保留内部历史，不能推送或对外附带其 Git 目录。
- 以 `public-sanitized` 的独立干净历史为发布基线，只加入核验后的文件快照。禁止合并 `master`，也不用全分支或镜像推送。
- 本地候选生成不会自动提交或更新发布分支。提交、推送、Release 和可见性变更以当次明确授权为准。
- 获准后，先同步和提交审核过的候选到干净历史，再显式仅发布该分支到远程 `main`。核对远程内容后再处理公开可见性和 Release。
- 若复用有历史的私有远程，公开前还要检查远程其他分支、标签、PR、Issue、附件与 Actions 记录，不能只检查默认分支当前文件。
