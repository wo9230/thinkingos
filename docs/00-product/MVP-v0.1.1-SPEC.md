# ThinkingOS v0.1.1 建造规格：事实库 · 采访引擎 · 模板适配器

**文档类型**：v0.1.1 施工规格（对 `MVP-v0.1.md` 的增量，不取代它）
**状态**：已接受（产品负责人 2026-09-02 确认），执行依据见 Decision Log `D-028`
**作用域**：在首批 5 次验证 Case 之前，为 v0.1 补齐「状态层」并压缩「规则层」；不改变 Quick / Full、非答案出口、CATALOG 与隐私铁律

---

## 1. 为什么

v0.1 建成三周后仍是零使用。需求确认（`SRC-010`）指出四个结构性原因，它们都不是「规则不够」：

1. 工具只能在本仓库目录内使用，而需要它的场景大多发生在别的项目目录、课程文件夹或纯生活问题里。
2. 没有持久的「关于本人」的编译层：每门课程、每个外部模板都在重问同样的八件事（做什么 / 产品线 / 客户 / 独特资源 / 数据在哪 / 重复动作 / 近期判断 / 卡在哪）。
3. 没有把空白**问出来**的机制：Skill 只回应已有的问题，不主动采访。
4. 复盘是产品核心，但没有任何东西把使用者带回到期的 Case。

同时，规则层已经过重：一次完整调用要加载接近九百行指令，先读规则再想问题。状态空、规则重，是反的。

## 2. 结构：Karpathy 三层 + 证据源

| 层 | 内容 | 谁维护 | 位置 |
|---|---|---|---|
| raw（不可改） | 真实 Case、录音转写、外部模板原件、原始倾倒 | 只追加 | `cases/`、`_private/raw/`、`_private/courses/` |
| compiled（编译层） | **事实库**：我是谁 / 我的生意 / 判断记录 / 当前现实 / 空白清单 | LLM 起草与追加，本人确认后改写顶部 | `_private/facts/` |
| schema | CATALOG 八环、Skill 路由器、采访引擎、模板适配器、Quick / Full 模板 | 产品文件，领域中立 | 公开仓库 |
| evidence（只读） | 个人知识库、专门方法索引、上游框架库 | 按需检索（`D-026`） | 仓库外 / `_private/method-routing/` |

五个操作：**倒**（ingest 混乱输入）· **问**（采访补空白）· **查**（检索证据源）· **收**（Quick / Full 落 Case）· **审**（到期复盘 + 规则淘汰）。

## 3. 事实库

```text
_private/                       ← 自己的 git 仓库（私有实例）；公开仓库已忽略
  facts/
    INDEX.md                    ← 每页一行：页名 / 一句话 / 最后核验日期 / 空白数
    00-我是谁.md
    01-我的生意.md
    02-判断记录.md
    03-当前现实.md
    04-空白清单.md
  courses/<模板名>/             ← 外部模板原件 + 输出副本
  raw/                          ← 录音转写、原始倾倒
  LOG.md                        ← 时间线，一行一事件
```

每页固定两段：**「当前最佳理解」**（可改写，只在本人确认后）与**「证据轨迹」**（只追加，每条带日期、来源、置信度）。

置信度四档（沿用人物研究方法论的分级）：`🟡 观察`（单一来源、未核验）· `🟢 可用`（两个独立来源或本人口述）· `🏆 确认`（本人审议确认）· `💎 直接`（有现实结果或原始记录支持）。矛盾标 `⚠`，保留双方，不静默取一边。

`00-我是谁` 必有「矛盾与阴影」「失败模式」两段；`03-当前现实` 必有「当前主线」字段（同一时间只允许一条）。答不上来的一律写 `〔空白〕` 并登记到 `04`，绝不补写。

## 4. 采访引擎（`references/interview.md`）

触发：本人要求「采访我 / 建档 / 填某份说明书」；事实库某页空白挡住当前判断；适配器发现空白。

1. 先读 `facts/INDEX.md` 与相关页，已有的不问。
2. 题由 CATALOG 八环生成：对目标产物先定首个断点环，只在该环出题；一组最多 3 问，答完再下一组。
3. 笼统答复追到一个数字、一个时间或一件具体事；独特资源要例子，形容词不算。
4. 答不上 → `〔空白〕` 进 `04`；与事实库或本轮前文冲突 → 当面指出，记 `⚠`，本人裁决。
5. 不夸、不总结成漂亮话，按 `00` 页记录的沟通偏好说话。
6. 每组答完即追加到对应页证据轨迹；顶部只在本人确认后改。
7. 结束报告：填了哪几页、剩几个空白。

## 5. 模板适配器（`references/adapt.md`）

输入任何外部模板（课程任务包、他人问卷、其他 Skill 的 schema）：

1. 原件存 `_private/courses/<名>/`。
2. 拆成字段清单，映射到事实库页与段；映射表展示给本人。
3. 已有 → 直接填并标来源；空白 → 只把这些交给采访引擎；对方架构中的**判断类内容**（方向清单、人格解读）→ 用 CATALOG 生成并标「本系统生成」。
4. 按对方要求的格式与落点输出；同时把新事实写回事实库。
5. 对方的数字与口径只引用不改写；对方的测试结果是「来源主张」，不是最高权威。
6. 结尾附映射表、空白清单，以及「对方问了事实库没有的字段 → 是否新增」。

## 6. Skill 拆分与规则预算

`SKILL.md` 压成路由器：≤ 120 行，只含工作模型、触发条件、硬护栏与引用表。硬护栏只保留可追溯到真实事故的五条：隐私、不编造、目标主权、不认可不可逆承诺、复盘不改写原判断。

按需加载：

| 文件 | 何时读 |
|---|---|
| `references/work.md` | Work 细则：宏大系统、穷举清单、把工具当解法、专门方法、跨模型恢复 |
| `references/formalize.md` | 用户要收束、落盘、计入验证（原 Step 0–5） |
| `references/review.md` | 到期复盘（原 Step 6）+ 复盘原则 + ROF 规则淘汰 |
| `references/interview.md` | 采访触发 |
| `references/adapt.md` | 收到外部模板 |
| `frameworks/CATALOG.md` | 定位到断点环之后 |
| `templates/*.md` | 落盘时 |

**ROF 规则淘汰循环**：每 3 个 Case，按需求理解 / 执行方式 / 结果质量 / 沟通效率四维评分，从未触发或造成摩擦的规则退役。规则只准减，不准净增，除非有新事故记录。

## 7. 复盘唤醒

`cases/INDEX.md`：Case / 视角 / 档位 / 处置 / 复盘日期 / 状态。Skill 启动先读它；今天 ≥ 复盘日期且未复盘则先报「N 个到期」，用户可跳过。文件不存在则跳过，不阻塞。落盘 Case 时同步加行。

## 8. 全局入口

启动器放在使用者自己的全局 Skill 目录（仓库外），是**唯一允许出现本机绝对路径的地方**。它做四件事：读并执行本仓库的 `clarify`，相对链接以仓库根解析；先读 `cases/INDEX.md`；指明事实库位置；在其他项目目录调用时，判断与采访结果只落本仓库，给当前项目的产物按当前项目规则写。本仓库不分发启动器，只在 README 说明如何写一个。

## 9. 不做

多模型编排、Python 引擎、YAML schema 校验、状态机、评测目录、UI、复制上游框架库、新建任何仓库。CATALOG、CONTEXT.md、两份模板、PRD-v0.2、v0.3 提案本次不动。

## 10. 验证

1. 从仓库外目录调用启动器 → 加载 clarify、读到 INDEX 与事实库。
2. 用一份真实外部模板跑适配器 → 对方格式的产物落在对方要求的位置，事实库同步更新，空白清单列出。
3. 私有实例 `git log` 有提交；公开仓库 `git status` 只含本规格列出的文件。
4. `AGENTS.md` 公开自检与本机 tripwire 通过。
5. `SKILL.md` ≤ 120 行；四个引用文件存在且被路由器引用。
