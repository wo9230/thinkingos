# 到期复盘与规则淘汰（按需读）

> 何时读：用户要求复盘指定记录、检查到期 Case，或进行规则淘汰。单纯日期到期不授权自动扫库、写回或创建提醒。

## Step 6 · 到期复盘

到达复盘日期后，先找回结果未知时的原始记录；**不改写当时的当前最佳判断、出口合同或决策快照**：

- 已落盘：读取指定原 Case；任务包含更新记录时，只在「到期复盘」区追加。仅分析则在当前对话交付，不自动写回。
- 仅在对话内完成：回到原对话或当时的一页式总结，在其后追加同样的复盘内容。
- 原始记录无法找回：不能声称完成复盘或形成 `Judgment Update`；保留这一缺口，重新从 Step 0 分流。

以下分支中的追加、更新或新建只适用于已获准的记录维护；仅分析时给出建议，不写文件。先按实际出口分支；初始为 Quick / Full 但中途转为非答案时，以记录的最终处置为准：

- `Quick`：执行下面的完整复盘。
- `no_framework`：记录可逆动作及观察结果；若结果暴露出新的判断问题，重新从 Step 0 分流，不倒填一份原本不存在的判断快照。原记录已落盘且新路由进入 Quick / Full 时，按 Step 5 新建双向链接的后续 Case。
- `evidence_first`：记录证据是否取得及其出处；取得后重新从 Step 0 分流，未取得则更新获取动作与返回日期。不得伪造原门槛、预测或 `Judgment Update`；进入 Quick / Full 时按 Step 5 承接记录。
- `cannot_proceed`：检查 blocker 与解除条件；已解除就重新从 Step 0 分流，未解除则更新去向与重访日期。不得伪造原门槛、预测或 `Judgment Update`；进入 Quick / Full 时按 Step 5 承接记录。
- `Full`：执行下面的完整复盘。

三个非答案分支若既不重进也不安排下一日期，必须记录关闭理由；这条同样适用于只存在于对话中的轻量自诊，不能因为没有模板就省略去向。

Quick / Full 正常决策的完整复盘：

1. 实际做了什么；未做、只做一部分也如实记录。
2. 观察到什么 `Outcome`，记录其来源、证据类型及观察 / 报告日期，再与原门槛或预测比较；没有结论也是合法结果。
3. 分开判断：当时的框定、证据、替代项、门槛与承诺是否合理且真实发生；结果中有多少来自执行、环境变化或运气。结果好不自动证明判断好，结果差也不自动证明判断差。
4. 提议 `Judgment Update`：维持 / 修订 / 放弃原判断，并写明是哪条新证据赚得了这次更新；证据不足就保持未决。由 `Case Owner` 明确确认、修订或拒绝，记录者不能代替 Owner 更新判断。
5. 给未解问题和下一动作安排去向；仍需观察时同时写下一动作的门槛 / 观察窗口和下一个复盘日期，不再观察则写明关闭理由，不能只写「结束」。

首批 5 次中，到期未完成复盘不取消原验证序号，但该 session 尚未提供 MVP §7 要求的验证证据；不得拿它证明复盘闭环已经成立。

## 复盘约束

1. **诚实面对数据**：做了几件就是几件，不美化。
2. **不贴标签**：记录事实，不写「我太懒」这类动机标签；标签不是证据。
3. **投入与问题相称**：沿用用户给定的时间预算；没有指定时不把固定时长当成通用门禁。
4. **调整有依据**：区分方法问题与方向假设，写清支持变更的新证据；不以固定月份禁止纠偏或风险止损。正式判断更新仍由本人确认。

## 规则淘汰循环（ROF）

规则层只准减，不准净增；新增规则必须挂一个真实事故。每 3 个 Case 做一次：

1. 汇总这 3 份记录末尾的三行（哪一步卡住 / 哪个问题白问 / 哪个步骤或检查多余）。
2. 四维打分（1–5）：需求理解 / 执行方式 / 结果质量 / 沟通效率；任一维 < 4 写明原因。
3. 对 SKILL.md 与 references/ 里的每条规则问两句：这 3 个 Case 里触发过吗？触发时帮了忙还是添了摩擦？
4. 从未触发 → 退役；触发但添摩擦 → 改写或退役；帮了忙 → 留。退役的规则移到本文末尾「已退役」表，不删。
5. 输出一份 Diff 给本人确认后再改文件；同时更新 `DECISION-LOG` 只在规则变更触及产品裁决时。
