# 建档采访包

> 用途：把一个人或一门生意的现实，用本人原话和数字建成事实库；再从事实推出待验证的方向假设。任何领域适用。
> 用法：对助手说「按建档采访包给我建档」。任务包含建档或使用事实库时才读取相关索引与页面；仅采访或填稿时使用本轮材料。只问影响目标产物的关键空白，保存范围与本人确认分别核实。外部机构发来自己的表格时，改走 `clarify` 的模板适配流程，本包作为默认产物结构。没有私有实例时按 [首次使用](../docs/00-product/FIRST-USE.md) 初始化空白结构。

## 铁律

1. 先复用本轮材料；使用事实库已获准时再读相关页。已有的不问，答不上的记〔空白〕，不替本人补写。
2. 一组最多三问，答完再下一组；笼统答复追到一个数字、一个时间或一件具体的事。
3. 不给建议、不夸、不把答复整理成漂亮话；本人要求时才转回分析。
4. 发现输入自相矛盾（目标与投入、时间与项目数、说法前后不一）当面指出，记 ⚠，由本人裁决。
5. 数字要出处；外部资料的数字只引用并标口径；没有出处写「待验证」。
6. 本人声明的不做清单与底线是硬边界：触碰的方案不写，改给替代形态。
7. 不为凑数生成：条数由证据决定。

## 交付一 · 事实底稿（对应事实库 00–03 页）

按事实库分页出题，顺序由「什么最挡事」决定，不按编号：

- **当前现实**：正在做什么、各做了多久、各自现状与一个数字；今天保哪一条当主线；可投入的时间、资金、人手；不可牺牲的边界。
- **对象与产品**：卖给谁或服务谁、为什么选你、抱怨过什么；产品或服务有几项、主力是哪项、彼此关系。
- **独特资源**：每条必须挂一个真实发生过的例子；形容词不算。
- **数据与重复动作**：数据在哪、由谁看、多久看一次；每周重复三次以上的动作按频次列。
- **近期判断**：最近一段时间做过的判断，当时依据、后来结果、什么证据会让当时的自己改主意。
- **卡点**：最想解决但一直没解决的一件事。

每节末尾标类型与置信度：🟡 观察（单一来源、未核验）· 🟢 可用（两个独立来源或本人口述）· 🏆 确认（本人审议确认）· 💎 直接（现实结果或原始记录支持）。模型推断另标「推断」，不自动升级。只有任务包含事实库维护、本人确认后才追加证据轨迹；页顶部的「当前最佳理解」同样须本人确认后修改。

## 交付二 · 三数核算

仅在目标产物需要时，用本人给的数字核算，缺数写〔空白〕。目标与投入必须对齐周期：例如年目标对应全年可投入总小时，不能直接除以每周小时；单次投入上限需有本人确认的总预算与比例；月度收支比较须说明支出是否已经计入，避免重复扣除。各项保留来源、单位与假设，结论为自洽 / 不自洽并写出差多少 / 数据不够算。不给建议。

## 交付三 · 方向假设清单

不是机会清单，是待验证假设。条数由事实底稿中 🟢 及以上的事实撑得住的数量决定。每条五段：

1. 方向一句话；
2. 依据的事实条目（引用底稿哪一节哪一句）；
3. 为什么现在可能有缝——写成假设；
4. 最便宜的验证动作 + 需要的数据来源；
5. 止损条件与投入上限。

仅在当前缺口需要时从 CATALOG 选零到两个框架，并检查「什么时候别用」；不因本模板叠加固定框架清单。触碰已知不做清单或底线的排除并标原因；主线或比较口径未确认时保留待定，不替本人选择。文件顶部写明：全部为待验证假设。

## 交付四 · 原始数据清单

仅列当前任务确需取得的原始数据：在哪 / 由谁取得 / 拟用文件名。这里的清单不授权读取、导出或发送资料，实际操作另按用户请求；取得不了的写〔空白〕。

## 交付五 · 自检与复盘约定

自检：用户所需产物是否交付、影响使用的〔空白〕与 ⚠ 是否说明；不以字数或五件齐全迫使用户完成无关部分。
复盘：确需观察方向假设时，与本人约定符合实际观察窗口的日期，回看哪些假设被支持或推翻、主线判断是否需要重访。仅在已有或获准创建正式 Case 且获准维护索引时更新 `cases/INDEX.md`；单纯采访、建档或填稿不自动生成 Case 或提醒。
