# 思想框架目录

**用途**：ThinkingOS 的判断内核。任何领域、任何人的问题，都从这里选工具，不从任何单一案例的经验里选。

**收录标准**：跨领域、跨年代被反复验证的通用规则。不收个人经验、不收行业土办法、不收时点性打法。

**每条必须有「什么时候别用」**——只说什么时候用的，是清单；说得出什么时候会误导的，才是框架。

**规模说明**：本目录收 35 条承重的。更全的评级体系见上游 `product-on-purpose/thinking-framework-skills`（135 个方法，带 S/M/P/V/A/C/X 七级证据分级，63 个已发布）。本目录是「够用的最小集」，不是要取代它。

## 一 · 看清现状：这到底是什么

| 框架 | 一句话 | 什么时候用 | **什么时候别用** |
|---|---|---|---|
| **第一性原理** | 拆到不可再拆的事实，从那里重新往上推 | 所有人都说「这行就是这么干的」时 | 时间紧、已有成熟解、重推成本远高于收益时。不是所有轮子都值得重造 |
| **约束理论 TOC** | 整条链的产出由最窄那一段决定，优化非瓶颈等于零 | 投了很多资源却没动静时 | 系统还没跑起来、没有稳定流程时——没有流就没有瓶颈 |
| **二八定律** | 大部分结果来自小部分原因 | 资源要分配、要砍东西时 | 长尾本身就是模式（保险、搜索）；或样本太小，20% 只有一两个，统计上无意义 |
| **MECE / 议题树** | 相互独立、完全穷尽地拆问题 | 问题一团糊，不知从哪下手 | 问题本质是涌现的、部分之和不等于整体时（文化、生态） |
| **事实/推断阶梯** | 观察 → 选择 → 解读 → 假设 → 结论，标清每句在哪一层 | 有人（包括自己）说得很确定时 | 日常低风险对话，会显得抬杠 |
| **五问法** | 连问五次为什么 | 找单一机械故障的近因 | **复杂系统别用**——它假设单线因果，会得出一个假根因然后停止调查 |

## 二 · 判断真假：怎么不骗自己

| 框架 | 一句话 | 什么时候用 | **什么时候别用** |
|---|---|---|---|
| **可证伪性** | 说不出什么证据能推翻它，它就不是判断，是信仰 | 任何要下结论的时刻 | 价值观和偏好本来就不可证伪，别拿去审它 |
| **基础率** | 先看这类事情**一般**的成功率，再看你这件的特殊性 | 估成功概率、做预测 | 确实是新品类、无同类可参照时（但先确认真的没有） |
| **参照类预测** | 别用你的故事推演，用同类项目的历史分布 | 估工期、估成本、估回报 | 参照类选错比不用更糟——先确认「同类」的定义站得住 |
| **逆向思维** | 与其问怎么成功，先问怎么必然失败，然后避开 | 目标模糊但失败模式清晰时 | 需要创造性突破时——避开所有坑往往等于原地不动 |
| **奥卡姆剃刀** | 同等解释力下选假设更少的 | 有多个解释在竞争 | 解释力**不**同等时。简单不等于对 |
| **幸存者偏差** | 你看到的样本已经被结果筛选过了 | 学习成功案例、看榜单时 | 样本已覆盖完整总体，或入选机制与所判断的结果无关时 |
| **Goodhart 定律** | 指标一旦成为目标，就不再是好指标 | 要设 KPI、设门槛时 | 短期、单次、无人博弈的度量 |

## 三 · 做选择

| 框架 | 一句话 | 什么时候用 | **什么时候别用** |
|---|---|---|---|
| **机会成本** | 真实成本是你放弃的最佳选项，不是花掉的钱 | 任何「要不要做」 | 选项之间不互斥时（能并行就别算成互斥） |
| **沉没成本** | 已经花掉的不进入决策 | 想「都投这么多了」时 | 声誉、承诺、关系有真实延续价值时——那不是沉没成本 |
| **单向门 / 双向门** | 可逆的决策快做，不可逆的慢做 | 决策速度焦虑时 | 误判可逆性时最危险——先问「撤回要多久、多少钱」 |
| **期望值** | 概率 × 后果，不只看概率 | 结果可量化、可重复下注 | 一次性、破产风险不可承受时（期望值为正也可能不该赌） |
| **最小可后悔** | 想象很老的时候回看，哪个更后悔 | 人生级、价值观级选择 | 日常运营决策——会把小事放大 |
| **边际分析** | 看下一单位的增量收益，不看平均 | 要不要再加一点投入 | 存在阶跃、临界点、网络效应时 |
| **凯利公式 / 仓位思维** | 下注大小比下注方向更决定长期结果 | 反复下注、有资金约束 | 单次决策；或概率估计本身很不可靠时 |

## 四 · 看生意

| 框架 | 一句话 | 什么时候用 | **什么时候别用** |
|---|---|---|---|
| **单位经济模型** | 一个客户/一单赚多少，回本要多久 | 判断生意成不成立 | 早期做发现、还在找 PMF 时——算得太早会杀掉对的方向 |
| **JTBD 待办任务** | 客户不是买产品，是雇它来做一件活 | 定位模糊、不知道卖点 | 需求已明确、竞争在效率而非定义时 |
| **漏斗 / AARRR** | 拆成获取→激活→留存→变现→推荐，看哪段漏 | 有流程有数据 | 非线性、口碑驱动、决策链复杂的 B2B 生意，硬套会失真 |
| **杠杆四型** | 劳动、资本、代码、媒体——后两个边际成本为零 | 判断某个打法能不能放大 | 手工交付本身就是价值时（高端咨询、定制） |
| **波特五力** | 供应商、买家、替代品、新进入者、现有竞争 | 判断一个行业结构上赚不赚钱 | 变化极快、边界模糊的新兴领域 |
| **飞轮 vs 漏斗** | 有没有一个环节的产出会变成下一轮的输入 | 找复利结构 | 一次性买卖 |

## 五 · 看长期与系统

| 框架 | 一句话 | 什么时候用 | **什么时候别用** |
|---|---|---|---|
| **二阶思维** | 「然后呢？」再问三次 | 所有看起来明显正确的动作 | 需要果断执行时——想太多阶会瘫痪 |
| **复利** | 小的持续优势在长时间尺度上碾压大的一次性优势 | 判断该做慢积累还是快收割 | 时间尺度不够长、或存在归零风险时（复利怕断） |
| **反脆弱 / 杠铃** | 极安全 + 小额高风险，避开中间地带 | 高不确定性环境下配置 | 可预测的稳态环境，中间地带才是最优 |
| **滞后与库存** | 系统的反馈有延迟，你现在看到的是过去的结果 | 改了没反应、或反应过度时 | 快反馈系统 |
| **熵与维护成本** | 任何系统不投入维护就会退化 | 决定要不要再建一个新东西时 | 一次性、用完即弃的产物；或退化损失可忽略、重建比维护更便宜时 |

## 六 · 落地执行

| 框架 | 一句话 | 什么时候用 | **什么时候别用** |
|---|---|---|---|
| **前置验尸** | 假设半年后这事彻底失败了，写下为什么 | 计划已成型、动手之前 | 探索阶段——会过早收紧 |
| **最小可行验证** | 用最小成本换最大不确定性的减少 | 关键假设未验证 | 假设已被验证、只差执行时。反复验证是另一种拖延 |
| **在制品限制 WIP** | 同时进行的事越多，每件完成得越慢 | 同时开了很多线 | 需要并行探索、且各线真的互不占用同一资源时 |
| **帕金森定律** | 工作会膨胀到填满给它的时间 | 定截止日 | 质量要求极高、返工代价大的工作 |

## 路由

不靠关键词匹配（说法千变万化，匹配必然漏）。**靠定位思考流水线上的断点**——任何问题、任何领域，卡住的地方必然落在八环之一。

### 第 0 步 · 先筛掉不该进来的

三问，命中任一条直接结束，不进路由：

| 问 | 命中则 |
|---|---|
| 代价低且可逆吗？ | 直接做。试错比分析便宜 |
| 是不是只缺一条具体信息，拿到就能定？ | 去取那条信息，不要套框架 |
| 是不是知道该干什么、就是不动？ | **不是认知问题**，是意愿、精力或恐惧。别拿框架当拖延工具 |

第三条最常被忽略。**很多时候人找框架，是因为不想动手。** 认出这一点比会用 35 个框架值钱。

### 第 1 步 · 定位断点

思考是一条有依赖的流水线，**上游坏了下游必然坏**——想不出选项，常常是因为问题框错了。

所以按顺序自检，**第一个答「不」的地方就是你的断点，不要往下找**：

| # | 环节 | 自检问题 |
|---|---|---|
| 1 | **框定** | 我能一句话说清要解决什么、以及什么结果算解决了吗？ |
| 2 | **事实** | 我说得出关键事实、以及每条的出处吗？分得清哪些是我推的吗？ |
| 3 | **因果** | 我说得出为什么会变成现在这样吗？ |
| 4 | **选项** | 我手上有两条以上**本质不同**的路吗？ |
| 5 | **评价** | 我有一把尺能比较它们吗？ |
| 6 | **风险** | 我说得出这条路会怎么崩、什么信号说明崩了吗？ |
| 7 | **顺序** | 我知道先做哪个、做到什么程度才进下一步吗？ |
| 8 | **执行** | 我做了，但结果出不来 |

八环 MECE：1–3 是**认识**，4–6 是**决策**，7–8 是**行动**。任何领域的任何卡点都落在这八环里。

### 第 2 步 · 环内选定（判据分叉，不是列候选让你挑）

**① 框定**

| 判据 | 用 |
|---|---|
| 被「这行就这么干」挡住 | 第一性原理 |
| 问题一大团，不知从哪切 | MECE / 议题树 |
| 问题关于「别人为什么要」 | JTBD |

**② 事实**

| 判据 | 用 |
|---|---|
| 证据主要来自成功案例、榜单、大 V | 幸存者偏差 |
| 需要知道「这类事一般是什么水平」 | 基础率 |
| 其余（默认入口） | 事实/推断阶梯 |

**③ 因果**

| 判据 | 用 |
|---|---|
| 有稳定流程，投了资源却没动静 | 约束理论 |
| 单点、机械、近因清晰 | 五问法（**复杂系统禁用**） |
| 有流程有数据，想知道哪段漏 | 漏斗 / AARRR |
| 改了没反应，或反应过度 | 滞后与库存 |
| 想知道后续连锁反应 | 二阶思维 |

**④ 选项**

| 判据 | 用 |
|---|---|
| 正着想不出别的路 | 逆向思维 |
| 想知道某条路能不能放大 | 杠杆四型 |
| 想找会自我增强的结构 | 飞轮 vs 漏斗 |
| 不确定性极高，不知道怎么配 | 反脆弱 / 杠铃 |

**⑤ 评价** —— 条目最多，先分对象：

- **评价的是一个解释/假设** → 多个解释在竞争用**奥卡姆剃刀**；检验单个结论用**可证伪性**
- **评价的是一门生意** → 单客算账用**单位经济模型**；看行业结构用**波特五力**
- **评价的是几个行动方案** → 继续分：

| 判据 | 用 |
|---|---|
| 卡在「都投这么多了」 | 沉没成本 |
| 纠结该快决还是慢决 | 单向门 / 双向门 |
| 只是「要不要再加一点」 | 边际分析 |
| 结果可量化，且是能重复下注的事 | 期望值；若还要定投入多少 → 凯利公式 |
| 人生级、价值观级、算不出来 | 最小可后悔 |
| 以上都不是（默认入口） | 机会成本 |

**⑥ 风险**

| 判据 | 用 |
|---|---|
| 方案已成型，动手之前 | 前置验尸 |
| 要设 KPI 或数字门槛 | Goodhart 定律 |
| 要新建一个东西 | 熵与维护成本 |
| 要估工期 / 成本 / 回报 | 参照类预测 |

**⑦ 顺序**

| 判据 | 用 |
|---|---|
| 不知道先修哪一段 | 约束理论（先修最窄的） |
| 已知瓶颈，不知资源投哪 | 二八定律 |
| 纠结慢积累还是快收割 | 复利 |

**⑧ 执行**

| 判据 | 用 |
|---|---|
| 关键假设还没验，不敢大投 | 最小可行验证 |
| 同时开了太多线 | 在制品限制 WIP |
| 没有截止日，无限膨胀 | 帕金森定律 |

> 约束理论、二八、WIP 在两环各出现一次——同一个工具，不同的活。第 3 环用它**找**瓶颈，第 7 环用它**排**顺序。

### 第 3 步 · 组合上限

一次最多两个。想要第三个时，通常不是信息不够，是在拖延。

只有两种组合成立：

- **跨环上下游**：前一环的产出是后一环的输入（③约束理论找出瓶颈 → ⑦二八决定在瓶颈上投哪 20%）
- **正反面**：一个论证，一个证伪（⑤单位经济算出能成 → ⑥前置验尸问怎么会崩）

**同环的两个不要叠**——它们在解同一道题。

### 兜底

| 情况 | 怎么办 |
|---|---|
| 八环都答得上「是」，但还是卡着 | 大概率是第 0 步第三条：不是认知问题 |
| 定位不了断点 | 从第 1 环重来。说不清要解决什么，就是框定没过 |
| 断点找到了，但该环所有框架都不适用 | 写下「断点在第 X 环，情境是 ___，现有工具都不匹配」。**这句话是往目录加新框架的唯一合法理由** |

### 新框架怎么入库

加一条必须同时给出三样，否则不收：

1. **挂在哪一环**（不能跨三环以上，那说明它不是框架是方法论集合）
2. **与同环其他条的判据差异**——什么情况该用它而不是同环那几个
3. **什么时候别用**

这样设计的结果：**加框架只动环内的判据表，不动路由本身。** 路由的骨架是八环流水线，它不随目录膨胀而变。

## 什么时候换掉手上这个框架

用了大约十分钟，出现下面任一条，立刻换，别硬撑：

| 信号 | 说明 |
|---|---|
| **没看见新东西** | 结论和开工前一样。框架的唯一价值是让你看见原来看不见的，看不见就是选错了 |
| **在给结论找证据** | 你在用它论证已有答案，不是在检验。这时它不是透镜，是化妆品 |
| **「什么时候别用」那一栏被你说服了** | 老老实实换 |
| **填不进去** | 硬套的地方就是它不适用的地方，不是你填得不对 |
| **越用越复杂** | 好框架让问题变简单。变复杂说明维度选错了 |

**35 条里一条都不合适，是正常的。** 这时候写下「这个问题的形状是 ___，现有工具都不匹配」——这句话本身就有价值，而且它是往目录里加新框架的唯一合法理由。

## 使用纪律

1. **框架是透镜，不是答案**。它决定你看见什么，不替你决定做什么。看完还是你自己拍板。
2. **必须过「什么时候别用」那一栏**。用在不适用的场景比不用更糟——它会给错误结论穿上严谨的外衣。
3. **用完写一句：它让我看见了什么之前没看见的**。写不出来，这次就是白跑，下次换工具。
4. **不收个人经验**。任何人（教练、大 V、你自己上次的成功）的单一经验都不进本目录，除非已经是跨领域反复验证的通用规则。个人经验只能作为一条待验证证据，进 case 文件，不进这里。
5. **框架服务于判断，不是判断的门槛**。任何时候都可以说「跳过，我直接做」。
